# Data sources and limitations

| Display data | Provider | How Kindle Sky uses it |
| --- | --- | --- |
| Nearby aircraft | [adsb.fi open data](https://github.com/adsbfi/opendata/blob/main/README.md) | One geographic request per refresh, normally every two minutes. |
| Satellites overhead | [CelesTrak GP orbital elements](https://celestrak.org/NORAD/documentation/gp-data-formats.php) | Downloads the `VISUAL` group in OMM/JSON at most once every two hours, plus the ISS record if absent, then estimates local sky positions on the Kindle. |
| Philadelphia-area rail | [SEPTA TrainView API](https://app.septa.org/) | Approximate Regional Rail train positions filtered to the saved coordinates and aircraft radius, normally queried every two minutes. |
| London-area rail | [TfL Unified API](https://push-api-nile.tfl.gov.uk/swagger/ui/index.html) | Finds the nearest rail station within 1.5 km of the saved coordinates, then shows its arrival predictions. These are station predictions, not train positions. |

The [adsb.fi open-data terms](https://github.com/adsbfi/opendata/blob/main/README.md) limit the public endpoint to personal, non-commercial use, request attribution with a link, and rate-limit public requests to one per second. Kindle Sky credits adsb.fi on screen and uses a longer default interval. [CelesTrak's usage policy](https://celestrak.org/usage-policy.php) asks clients to retrieve GP data only once per two-hour update and to stop automated requests after HTTP errors. Kindle Sky caches the catalog across restarts, follows that interval, and pauses catalog requests after an HTTP error until a manual retry. Check each provider's current terms before deploying beyond personal use.

Aircraft positions and metadata can be missing, stale, or wrong. The "reported military" label comes from a feed flag and is not independent verification. The rare-type list is a small, hand-selected set, not a comprehensive rarity database. Aircraft silhouettes and satellite and train drawings are representative diagrams, not exact vehicles or spacecraft.

The satellite view tracks a curated bright-satellite group, not every object in orbit. It shows objects at least 10° above the saved location's horizon, sorted by elevation; the ISS is featured when above 20°. The local calculation uses Kepler motion with a J2 drift correction. CelesTrak's GP elements are designed for SGP4, so these directions are **approximate** and may drift with age, especially near the horizon. Elements older than three days are ignored. "Possibly visible" means the model puts the satellite in sunlight while the Sun is at least 6° below the local horizon. It does not account for weather, light pollution, atmospheric effects, or the object's actual brightness. There are no pass alerts or precise pass times.

Rail coverage is chosen from the location saved in Kindle Sky. Philadelphia-area coordinates select SEPTA; Greater London coordinates select TfL; other locations skip the train view. There is no automatic GPS location detection. SEPTA TrainView may place trains approximately, especially in areas without live location data; a train's displayed line may lag its current operating segment. TfL predictions can change or be absent, and only the nearest station within 1.5 km is shown. [TfL's API portal](https://api-portal.tfl.gov.uk/products) allows 50 anonymous requests per minute; Kindle Sky normally makes one stop search when the location changes and one arrival request per two-minute refresh in London. TfL data is credited on screen and no TfL logos are used.

Kindle Sky sends the configured latitude and longitude to adsb.fi in API requests. In London it also sends them to TfL for the nearest-station search. The CelesTrak and SEPTA requests contain no coordinates; the Kindle filters or calculates positions locally. It sends no account credentials and has no project-operated server. If an aircraft or rail request fails, previously received data is marked **STALE** and removed after ten minutes without an update. Cached satellite elements can continue to supply approximate sky positions until they are three days old.

The plugin uses KOReader's CA bundle to verify the certificate chain for each HTTPS feed, rejects redirects, and caps responses at 2 MiB. KOReader's bundled LuaSec build does not expose hostname verification, so a certificate for an unrelated trusted site could still be accepted. Feed data should not be treated as an authenticated alert. If the CA bundle is missing or certificate verification fails, the display shows the feed as unavailable rather than retrying without verification. The clock uses the selected time zone; Auto falls back to Eastern when KOReader reports UTC.

KOReader is a separate project; install it from its [official release and installation documentation](https://github.com/koreader/koreader). The plugin does not include KOReader binaries or a launcher. The project's e-ink diagrams and plugin logic were created for Kindle Sky, inspired by the [original desk-display idea](https://www.reddit.com/r/eink/comments/1xbw3xi/i_built_an_epaper_desk_display_that_shows_nearby/).
